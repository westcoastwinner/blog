## 支付/订单

### 下单支付流程设计

1. 用户提交下单请求：创建业务订单（biz_order）

后端做：

- 校验库存（有些领域要锁库存）
- 计算商品金额、优惠金额
- 校验用户信息（地址、身份等）
- 生成 **business_order**（例如 `biz_order_no`）
- 将订单状态设为：`UNPAID`

👉 这一步不会调支付。

2. 用户点击“去支付”：创建 payment_order

后端做：

- 生成 payment_no（支付订单号）
- 写入 payment_order 表（status = INIT）
- 持久化支付金额、渠道、用户等信息
- 返回给前端“调起支付所需参数”（来自调用支付平台返回的参数）

一条 business_order 对应一条 payment_order.如果失败重新支付，也可以多条 payment_order。

3. 用户实际付款（在第三方）

这是在微信/支付宝界面发生的，与你的系统无关。

4. 支付渠道回调（notify）

你的支付服务要做 5 件事：

- **验签**（必须）
- **查询 payment_order**（根据 channel_trade_no / payment_no）
- **幂等处理**（status 已是 SUCCESS 就直接返回）
- **更新状态**：`INIT → PROCESSING → SUCCESS`
- **记录对账信息**（notify_raw_data）

你要在自己的系统真正把这条 payment_order 记为 SUCCESS。

5. 通知业务订单系统（via MQ / RPC）

支付成功后，需要：

- 通知订单服务：biz_order_no = XXX 已支付
- 订单服务将 business_order 状态改为 PAID
- 执行后续流程（发货、生成卡密、发放课程……）

为了防止支付成功但消息丢失，需要：

✔ 支付服务 → MQ（可靠消息）
 ✔ 订单服务 → 消费消息，更新业务订单



#### **支付保护机制**

最核心的即两点：**调起**和**回调**。这两个步骤需要一套“保护措施”：

调起：1.参数校验。你要校验的：金额只能来自数据库，不允许从前端读（前端可被篡改JS 可修改抓包可以改）；biz_order_no 必须是可支付状态（UNPAID）等。2.生成签名（例如 RSA2、HMAC-SHA256）。以支付宝为例，支付前你要：构造请求参数（按 key 排序）--拼接成字符串--使用你系统的私钥 `RSA2` 私钥对其进行签名--把签名和公钥证书传给支付宝。支付宝会用你的**公钥**去验签，从而确认这真的是你系统发起的请求，并且参数未被篡改。（微信支付 v3 使用：商户私钥签名（SHA256 with RSA）HTTP 头中带 `Authorization`平台证书校验响应签名）

👉 **核心思想：你私钥签，渠道公钥验。渠道私钥签，你公钥验。**

这是支付安全的根。



回调：“回调通知”环节是支付系统安全最关键的部分

攻击者最常干的事情就是：
 **伪造支付成功回调，诱导系统发货。**

你必须保证两件事：

1. **回调内容确实来自渠道**
2. **回调内容没有被篡改**

支付渠道公布了一套加密 / 签名规则，你必须通过这些规则确认其真实性。

------

✔ 1. 回调参数校验（防止攻击者伪造）

常见校验：

- 检查 amount 与 payment_order 里的金额一致（金额不能被改）
- 检查支付状态字段是否合法
- 检查 app_id / merchant_id 是否与自己配置的一致

金额校验是最关键的一条：

> **回调金额 ≠ 订单金额 → 直接拒绝**

这是杜绝攻击者篡改金额的基础。

------

✔ 2. 验签（RSA / ECDSA）

回调阶段使用的是：

👉 **渠道私钥签名，你用渠道公钥验签**

例如：

✓ 支付宝回调验签流程

1. 回调参数里带 `sign` 和 `sign_type`
2. 对所有参数（除 sign）排序后拼接成待验签字符串
3. 使用支付宝的公钥（你提前配置）去验签：

```
boolean result = AlipaySignature.rsaCheckV1(
    params, 
    alipayPublicKey, 
    "UTF-8", 
    "RSA2"
);
```

若验签失败：

- 不处理支付结果
- 返回 `fail`
- 支付宝会继续推送回调

------

✓ 微信支付 v3 验签流程

微信 v3 回调采用：

- 平台私钥签
- 商户（你）用微信平台公钥验

流程稍复杂：

1. 读取回调 HTTP header：

- `Wechatpay-Timestamp`
- `Wechatpay-Nonce`
- `Wechatpay-Signature`
- `Wechatpay-Serial`

1. 使用微信平台证书做检验：

```
validator.validate(
    timestamp, nonce, body, signature
);
```

1. 若通过，解密 encryptData：

```
AesUtil aes = new AesUtil(apiV3Key.getBytes());
String result = aes.decryptToString(associatedData, nonce, cipherText);
```

#### 幂等机制

**防止回调多次造成重复发货**

支付渠道的回调机制是“至少一次”，不是“仅一次”。

如果你不做幂等，可能会出现：

- 1 次付款
- 3 次回调
- 3 次发货

👉 所以必须实现**幂等性更新**。

实现方式：

1. payment_order.status = SUCCESS 的订单
   - 不再重复处理
2. 更新成功必须保证 **行级乐观锁 version**
3. 用支付订单号（payment_no）作为幂等锁

伪代码：

```
if (paymentOrder.getStatus() == SUCCESS) {
    return OK;
}

int updated = update payment_order set 
  status=SUCCESS 
where payment_no=? and version=?;

if(updated == 0){
    // 别人更新了，说明不是第一次回调
    return OK;
}
```

这样你就永远不会重复处理一笔支付。

### 状态机设计

| 状态         | 含义                                         |
| ------------ | -------------------------------------------- |
| `CREATED`    | 支付订单已生成，还未调渠道                   |
| `PENDING`    | 已调渠道，等待用户支付完成                   |
| `PROCESSING` | 渠道已回调，但结果未最终确认（幂等重试常见） |
| `SUCCESS`    | 支付成功                                     |
| `FAILED`     | 支付失败（用户取消、超时…）                  |
| `CLOSED`     | 主动关闭（如超时未支付）                     |
| `REFUNDING`  | 退款处理中                                   |
| `REFUNDED`   | 已退款                                       |

public class ReconciliationParserFactory {

    private HashMap<String, ReconciliationFileParser> parserMap = new HashMap<>();

    @Autowired
    public ReconciliationParserFactory(List<ReconciliationFileParser> parsers) {
        // 自动收集所有策略实现
        parsers.forEach(parser -> {
            if(parser instanceof DetFileParser){
                parserMap.put("det",parser);
            }else if (parser instanceof ChkFileParser) {
                parserMap.put("chk",parser);
            }
        });
    }

    public ReconciliationFileParser getParser(String fileName) {
        if (fileName == null || !fileName.toLowerCase().endsWith(".txt")) {
            log.error("仅支持 txt 文件，收到：" + fileName);
            throw new RuntimeException("仅支持 txt 文件，收到：" + fileName);
        }

        //文件格式应为: 市场编号-日期-chk.txt  市场编号-日期-det.txt
        String suffix = fileName.substring(fileName.lastIndexOf("-") + 1)
                .replace(".txt", "");

        ReconciliationFileParser parser = parserMap.get(suffix);
        if (parser == null) {
            log.error("未找到解析器: " + fileName);
        }
        return parser;
    }
}

@Component
@Slf4j
public class DetFileParser implements ReconciliationFileParser {
    @Resource
    private DetFileMapper detFileMapper;

    private static final Map<String, String> COLUMN_FIELD_MAP = new HashMap<>();

    //为防止建行推送文件中的字段乱序\不一致\错误等情况出现，特此维护
    static {
        COLUMN_FIELD_MAP.put("Main_Ordr_No", "mainOrdrNo");
        COLUMN_FIELD_MAP.put("SN", "sn");
        COLUMN_FIELD_MAP.put("Py_Ordr_No", "pyOrdrNo");
        COLUMN_FIELD_MAP.put("RcvPymt_AccNo", "rcvPymtAccNo");
        COLUMN_FIELD_MAP.put("RcvPrt_Mkt_Mrch_ID", "rcvPrtMktMrchId");
        COLUMN_FIELD_MAP.put("RcvPrt_Mkt_Mrch_Nm", "rcvPrtMktMrchNm");
        COLUMN_FIELD_MAP.put("ClrgAmt", "clrgAmt");
        COLUMN_FIELD_MAP.put("Clrg_StCd", "clrgStCd");
        COLUMN_FIELD_MAP.put("Clrg_Dt", "clrgDt");
        COLUMN_FIELD_MAP.put("HdCg_Amt", "hdcgAmt");
        COLUMN_FIELD_MAP.put("Sub_Ordr_No", "subOrdrNo");
        COLUMN_FIELD_MAP.put("Shld_Subacc_Amt", "shldSubaccAmt");
        COLUMN_FIELD_MAP.put("Udf_Id", "udfId");
    }

    @Override
    public void parse(InputStream inputStream,String fileName) {
        try (BufferedReader br = new BufferedReader(new InputStreamReader(inputStream))) {
            String headerLine = br.readLine(); // 第一行列名
            if (headerLine == null) return;
            log.info("***解析开始, filename:{}, headerLine:{}***", fileName,headerLine);
            String[] headers = headerLine.split("\\|");
            String line;
            //循环读取txt文件的每一行数据并解析
            while ((line = br.readLine()) != null) {
                if (line.trim().isEmpty()) continue;

                String[] cols = line.split("\\|", -1);

                LedgerDetail detail = new LedgerDetail();

                for (int i = 0; i < headers.length; i++) {
                    String colName = headers[i].replace("\uFEFF", "")   // 去 BOM
                            .replace("\u00A0", "")   // 去 NBSP
                            .trim();
                    String value = cols.length > i ? cols[i] : "";
                    String fieldName =COLUMN_FIELD_MAP.get(colName);
                    if (fieldName == null) continue;//防止CCB给了一个不存在的列名

                    setFieldValue(detail, fieldName, value);
                }

                // ============ 增量更新逻辑 根据SN查询是否存在记录，若无则说明是新纪录，需写入============
                LambdaQueryWrapper<LedgerDetail> wrapper = new LambdaQueryWrapper<>();
                wrapper.eq(ObjectUtils.isNotEmpty(detail.getSn()),LedgerDetail::getSn, detail.getSn());
                LedgerDetail exist = detFileMapper.selectOne(wrapper);

                if (ObjectUtils.isEmpty(exist)) {
                    String uuid = IdUtil.simpleUUID();
                    detail.setId(uuid);
                    detFileMapper.insert(detail);
                } else {
                    /*
                     * 增量更新时，前面的旧记录不做处理（默认银行不会更新旧记录）
                     * */

//                    log.info("SN(分账明细主键):{}, 检测到表中已存在该SN记录，执行操作：更新记录", detail.getSn());
//                    detail.setId(exist.getId());
//                    detFileMapper.updateById(detail);
                }
            }

        } catch (Exception e) {
            log.error("解析分账明细文件失败：" + fileName, e);
            throw new RuntimeException("解析分账明细文件失败：" + fileName, e);
        }
    }

    private void setFieldValue(LedgerDetail obj, String fieldName, String rawValue) {
        if (rawValue == null) rawValue = "";
        try {
            Field field = LedgerDetail.class.getDeclaredField(fieldName);
            field.setAccessible(true);

            if (field.getType() == BigDecimal.class) {
                if (rawValue.isEmpty()) {
                    field.set(obj, null);
                } else {
                    field.set(obj, new BigDecimal(rawValue));
                }
            } else {
                field.set(obj, rawValue);
            }

        } catch (Exception e) {
            log.error("字段映射失败: " + fieldName + " 原始值: " + rawValue, e);
            throw new RuntimeException("字段映射失败: " + fieldName + " 原始值: " + rawValue, e);
        }
    }
}
